# NovaUI Core

A React component studio with light and dark themes for **Codemore · Week 3 · Task 4 — Introduction to Testing Frameworks**. Explore four reusable UI components, change their properties, inspect usage examples, and verify their behavior with Jest and React Testing Library.

## Features

- **Button:** primary, secondary, ghost, and danger variants; three sizes; disabled and loading states; icon support; native keyboard activation.
- **FormInput:** unique IDs, associated labels, required and disabled states, controlled input support, and accessible hints and validation errors.
- **LoginForm:** empty-field, email-format, and password-length validation; password visibility; a preference checkbox; local success state and reset.
- **UserCard:** profile details, derived initials, availability state, a compact layout, saved profiles, and a keyboard-dismissable contact dialog.
- **Component studio:** searchable catalog, live property controls, generated button usage code, code copying, JSON configuration export, and an event activity log.
- **Quality dashboard:** actual saved test and coverage results, generated by Jest.
- Responsive layouts, a persistent light/dark theme toggle, visible focus outlines, a skip link, keyboard-operated tabs, and reduced-motion support.
- Local Git history and a GitHub Actions workflow that runs tests, generates coverage, and builds the application.

## Setup

Use **Node.js 20.19+ or 22.12+** (Node 24 recommended) and npm. Open this folder in VS Code, then run:

```sh
npm install
npm run dev
```

Open the Local URL printed in the terminal, usually `http://127.0.0.1:5173/`. The port automatically increments if it is occupied.

The VS Code tasks menu includes **NovaUI: Start studio**, **NovaUI: Test with coverage**, and **NovaUI: Production build**.

## Commands

| Command                 | Purpose                                                 |
| ----------------------- | ------------------------------------------------------- |
| `npm run dev`           | Start the local development server                      |
| `npm test`              | Run all automated tests                                 |
| `npm run test:watch`    | Re-run affected tests while developing                  |
| `npm run test:coverage` | Run the suite and produce full coverage reports         |
| `npm run test:report`   | Refresh the recorded summaries and the in-app dashboard |
| `npm run build`         | Build the production application into `dist/`           |
| `npm run preview`       | Preview the production build locally                    |

Open `coverage/index.html` after a coverage run for the detailed HTML report. This generated directory is excluded from Git; the portable summaries in `reports/` are tracked.

## Recorded validation

The completed project passes **57 tests across 6 suites**. Coverage of all four reusable components and the validation helper is **100% for statements, branches, functions, and lines**. The production build also passes.

Coverage is deliberately collected from `src/components/**/*.jsx` and `src/lib/**/*.js`. These are the assignment’s reusable units. The studio shell is exercised separately by integration tests; its coverage is not included in the reported percentage.

Jest enforces the following minimums:

| Metric     | Required | Recorded |
| ---------- | -------- | -------- |
| Statements | 90%      | 100%     |
| Branches   | 85%      | 100%     |
| Functions  | 90%      | 100%     |
| Lines      | 90%      | 100%     |

See `reports/TEST-RESULTS.md` for the timestamped per-file summary and `reports/coverage-summary.json` for the machine-readable version. Re-run `npm run test:report` after changing a component. The studio report is a recorded snapshot, and does not run Jest in the browser.

## Testing methodology

The suite uses **Jest 30**, **jsdom**, **React Testing Library**, **jest-dom**, and **user-event**. Babel transforms JSX for Jest; Vite builds the browser application.

Tests interact with components through roles, labels, and user-visible content. They verify behavior rather than relying on implementation snapshots.

- `Button.test.jsx`: initial rendering, forwarded props, every variant and size, click callbacks, Enter activation, disabled behavior, loading, and decorative icons.
- `FormInput.test.jsx`: label relationships, generated and explicit IDs, typing, required props, accessible descriptions, error precedence, disabled inputs, and unique IDs.
- `validation.test.js`: blank and whitespace-only email, malformed addresses, password boundaries, and valid credentials.
- `LoginForm.test.jsx`: invalid submissions, clearing errors on edits, visibility toggling, successful submissions, callback arguments, reset, optional callbacks, and Enter submission.
- `UserCard.test.jsx`: profile structure, initials and status fallbacks, selected state, save/contact callbacks, compact mode, and optional callbacks.
- `App.test.jsx`: search, button properties and activity, persistent saved cards, dialog focus, live form submission, and navigation between code, tests, reports, and documentation.

## Component usage

```jsx

  type="email"
  value={email}
  onChange={event => setEmail(event.target.value)}
  hint="Use your sample email address."

  user={{ name: 'Maya Shah', role: 'Designer', email: 'maya@example.com' }}
```

Components use the shared classes in `src/styles.css`. Include the relevant styles when reusing them in another application.

## Demo behavior and data

The login form is a component demonstration, not an authentication service. Use sample details such as `demo@example.com` and `sample123`. It sends no network requests, clears the password after successful validation, and passes only `{ email, remember }` to the demo callback. The checkbox is part of the tested form payload; it does not retain credentials.

Saved profile IDs are retained under `novaui-saved` in browser local storage. The selected theme is retained under `novaui-theme`, defaults to light, and is applied before rendering to avoid a flash on reload. Other controls and event activity last only for the current session. The profile contacts are sample addresses. Configuration export contains component settings, not entered login details. Google Fonts supplies the typefaces when online; system fonts provide the fallback.
